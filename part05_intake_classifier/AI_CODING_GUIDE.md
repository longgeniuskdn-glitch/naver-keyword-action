# 코딩 AI 공통 작업 가이드

이 문서는 Codex, Claude Code, Cursor, OpenCode, Gemini CLI, Copilot 또는 파일을 읽고 수정할 수 있는 다른 코딩 AI에 공통으로 사용합니다.

## 첫 분석 요청

```text
이 프로젝트를 수정하지 말고 먼저 분석하라.

1. 프로그램의 목적
2. 실행 방법
3. 주요 파일과 함수의 역할
4. SQLite 데이터 구조
5. 분류 규칙과 위험 표시 위치
6. 중복 차단 방식
7. 자동 테스트 8개의 목록
8. 사람이 승인해야 하는 행동
9. 잘못 수정했을 때 되돌리는 방법

내 승인 전에는 파일을 수정하지 마라.
```

## 첫 기능 추가 실습

목표: 분류 결과에 `예상 응답 기한`을 추가합니다.

```text
기존 기능을 삭제하지 말고 예상 응답 기한 기능의 변경 계획만 작성하라.

규칙 예시:
- high: 2시간 안에 확인
- medium: 영업일 기준 1일 안에 확인
- low: 영업일 기준 3일 안에 확인

먼저 다음을 보고하라.
1. 변경할 파일과 함수
2. 데이터베이스에 새 열이 필요한지
3. 기존 데이터 호환 방법
4. 화면 변경
5. 추가할 테스트
6. 되돌리는 방법
7. 개인정보와 외부 실행 영향

내 승인 전에는 코드를 수정하지 마라.
```

## 수정 승인 후 완료 기준

- 기존 8개 테스트가 통과합니다.
- 새 기능 테스트가 추가됩니다.
- 기존 DB를 삭제하지 않습니다.
- 같은 입력의 중복 차단이 유지됩니다.
- 외부 답장 기능을 추가하지 않습니다.
- 변경 이유와 테스트 결과를 `CHANGELOG.md`에 남깁니다.

## 오류 수정 요청

```text
아래 오류를 고치기 전에 원인을 설명하라.

실행 환경: [운영체제와 Python 버전]
실행 명령: [명령]
기대 결과: [기대]
실제 결과: [비밀정보를 지운 전체 오류]
최근 변경 파일: [파일]
백업 위치: [위치]

먼저 가장 가능성 높은 원인 3개, 확인 방법, 수정할 파일, 데이터 영향, 테스트와 되돌리는 방법만 보고하라. 내 승인 전에는 파일을 수정하지 마라.
```

## 금지사항

- 실제 이메일과 메신저에 자동 답장 추가 금지
- 환불, 송금, 계약 확정과 법률 판단 자동화 금지
- 데이터베이스 삭제 또는 원본 덮어쓰기 금지
- 테스트를 통과시키기 위해 안전 검사를 제거하지 않기
- 개인정보를 로그나 화면에 새로 노출하지 않기
- 여러 기능을 한 번에 수정하지 않기
