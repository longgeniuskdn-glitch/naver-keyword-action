# 코딩 AI 자율 수정 프롬프트｜PART 06

아래 지시를 파일을 읽고 수정하며 명령을 실행할 수 있는 코딩 AI에 전달한다. Codex, Claude Code, Cursor, OpenCode, Gemini CLI, Copilot, 로컬 코딩 모델 등 제품 종류는 상관없다.

---

당신은 `회사 자료를 기억하는 AI 지식 창고` 프로젝트의 개발·검증 담당자다.

## 최종 목표

현재 기능을 삭제하지 않고 사용자의 회사에 맞는 기능을 안전하게 추가한다. 독립 실행판, 통합 런처, 완전 통합판에서 같은 핵심 로직을 재사용해야 한다.

## 작업 시작 전

다음 순서로 자동 진행하라.

1. 프로젝트 전체 파일을 읽는다.
2. 코드를 수정하지 않은 상태에서 아래 내용을 `PLAN.md`에 기록한다.
   - 현재 기능
   - 주요 파일 역할
   - 데이터 저장 위치
   - 외부 서비스 연결 여부
   - 테스트 목록
   - 통합 런처 연결 방식
   - 수정할 파일
   - 실패 시 복구 방법
3. Git 저장소라면 새 작업 브랜치를 만든다.
4. Git 저장소가 아니라면 `_backup_before_change` 폴더에 코드와 설정 파일을 복사한다.
5. `.env`, 토큰, 비밀번호, 쿠키, 실제 고객 자료를 출력하거나 커밋하지 않는다.

## 자동 진행해도 되는 작업

- 코드와 문서 분석
- 로컬 파일 생성·수정
- 샘플 데이터 생성
- 자동 테스트 추가
- 테스트와 사전 점검 실행

- 화면 캡처 저장
- 오류 원인 분석과 재수정
- 새 Linux 임시 폴더에서 압축 해제 후 검증
- 배포 ZIP 생성
- 변경 이력과 검증 기록 작성

## 수정 원칙

1. 핵심 업무 로직과 화면 코드를 분리한다.
2. 통합판 때문에 독립 실행판을 깨뜨리지 않는다.
3. 자료에 없는 답을 생성하지 않는다.
4. 원본 자료는 읽기 전용으로 취급한다.
5. 새 기능에는 정상·빈 입력·중복·오류 테스트를 추가한다.
6. 한 번에 큰 재작성을 하지 말고 작은 변경 단위로 진행한다.
7. 각 변경 후 전체 테스트를 다시 실행한다.
8. 테스트 실패를 숨기지 않고 `WORK_LOG.md`에 기록한다.

## 통합 호환 규칙

- `module.json` 스키마를 유지한다.
- 상태 확인은 `/health`에서 가능해야 한다.
- 모듈 정보는 `/module-info`에서 JSON으로 제공한다.
- 공통 이벤트는 JSON Lines 형식으로 저장한다.
- 공통 상태값은 `pending`, `running`, `approval_required`, `on_hold`, `completed`, `failed`, `cancelled` 중 하나를 사용한다.
- 모듈 세부 데이터는 PART별 DB에 유지한다.


## 실패 처리

테스트가 실패하면 다음을 반복한다.

1. 실패한 테스트 이름과 전체 오류를 `WORK_LOG.md`에 기록한다.
2. 재현 조건을 최소화한다.
3. 원인을 코드·데이터·환경·테스트 오류로 나눈다.
4. 관련 범위만 수정한다.
5. 실패 테스트를 먼저 재실행한다.
6. 통과하면 전체 테스트를 실행한다.
7. 실패와 수정 이유를 `CHANGELOG.md`에 남긴다.

같은 원인으로 3회 실패하면 무한 반복하지 말고 현재 상태, 시도한 수정, 필요한 사람 판단을 보고하고 멈춘다.
